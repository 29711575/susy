# 后续单轮任务格式

用途：给Codex/合作者的工作单；填写具体范围后才是任务。阅读本模板不授权执行。

```text
本轮目标：一句话说明要回答的问题及其与GOAL-01的关系。

先读：AGENTS.md、docs/RESEARCH_CHARTER.md、docs/STATUS.md。
相关规范：只列本轮需要的OBS/NUM/DRV条目与ADR。
当前基线：真实工作树、HEAD/dirty状态、输入/旧audit路径。

允许做：精确到模块、文件或数据范围。
不允许做：例如不改采样、不新增QMC、不提交HPC、不commit。
完成条件：可验证的行为、对照和输出；不把预期物理结果写成必须得到的答案。
测试/预算：哪些测试、是否允许短运行、规模和停止条件。

交付：修改清单、实际命令/结果、证据路径、尚未确认项。
知识更新：仅在发生状态/定义变化时更新STATUS/相关ADR；保留旧audit。
```

## 防止上下文丢失的最低交付

一次实质性工作结束后，报告应能回答：为什么做、实际做了什么、什么证据支持、没有证明什么。只需几段，不要求每轮重写全部物理背景。

源码commit不足以标识带未提交修改的运行；运行依据应可追到实际修改或打包校验。多条独立seed、不同构建和不同协议保持可区分。

新对话的最小上下文：AGENTS、CHARTER、STATUS、相关ADR、相关代码快照、最新audit报告。未提供的大目录用路径和文件清单标明，不假装另一工具可访问本地路径。
